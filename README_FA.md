## چکیده فنی

معماری سنتی میزبانی وردپرس بر پایه مدل منسوخ «عدم اشتراک حافظه» (Shared-Nothing CGI / PHP-FPM) مربوط به دهه ۱۹۹۰ استوار است. در ترافیک‌های سنگین هم‌روند، این معماری با گلوگاه‌های زیرساختی متعددی مواجه می‌شود:
- اسکن مجدد سیستم فایل و پارس کدهای بایت‌کد در هر درخواست ورودی HTTP.
- سربار سنگین سریالایز کردن داده‌ها و تأخیر شبکه برای ارتباط با سرورهای کش خارجی (مانند Redis یا Memcached).
- تأخیر اتصال و دست‌دهی بلاک‌کننده سوکت‌ها برای هر تراکنش با پایگاه داده.
- نیاز به استقرار مجموعه‌ای از سرویس‌های مجزا شامل Linux، Nginx، PHP-FPM، MySQL و Redis به صورت همزمان.

پروژه **AR-WP** کل چرخه حیات اجرای وردپرس را از ابتدا بازطراحی کرده است. این ران‌تایم با تکیه بر قابلیت‌های ایمنی حافظه و پردازش غیرهمگام (Async) زبان راست، هسته اصلی و دست‌نخورده وردپرس را به صورت یک باینری مستقل و مقیم در حافظه بدون نیاز به هیچ دیمن یا سرویس خارجی اجرا می‌کند.

## تمایزهای کلیدی در معماری

### ۱. کش اشیاء مقیم در حافظه مشترک (DashMap)
در وردپرس سنتی، ذخیره آبجکت‌ها نیازمند ارسال داده از طریق سوکت TCP/Unix به ردیس است. در AR-WP، یک جدول هش اشتراکی و بدون قفل (`DashMap`) مستقیماً درون پردازه ران‌تایم راست تعبیه شده است:
- **تأخیر در مقیاس میکروثانیه:** کلیه فراخوانی‌های کش بدون کوچک‌ترین سربار شبکه و مستقیماً روی رم پردازنده اجرا می‌شوند.
- **توابع نیتیو موتور:** توابع در سطح هسته تعریف شده و از طریق دراپ‌این استاندارد `dropins/object-cache.php` در اختیار وردپرس قرار می‌گیرند.

### ۲. استخر اتصالات دیتابیس و پل تعبیه‌شده
- **ارتباط همروند با MySQL:** حذف دست‌دهی‌های مکرر TCP و احراز هویت دیتابیس در هر ریکوئست با استفاده از Connection Pool نیتیو راست.
- **پل دیتابیس درونی (SQLite / PDO):** ارائه درایور `dropins/db.php` که امکان اجرای کامل وردپرس را بدون نیاز به نصب سرور MySQL به صورت محلی و تک‌فایلی فراهم می‌سازد.

### ۳. وب‌سرور غیرهمگام مجتمع (Tokio / Axum و CLI SAPI)
نیاز به وب‌سرورهای واسط مانند Nginx یا آپاچی به طور کامل حذف شده است:
- توزیع پردازش بر روی هسته‌های مختلف CPU با استخر پردازشی اختصاصی (Worker Pool).
- سرو فایل‌های استاتیک (CSS, JS, Fonts) با رویکرد Zero-Copy و بازدهی حداکثری.
- مدیریت استاندارد درخواست‌های HTTP، بارگذاری سوپرگلوبال‌ها (`$_SERVER`, `$_GET`, `$_POST`, `$_COOKIE`, `$_FILES`) و پاسخ‌های شبکه.

## وضعیت سازگاری آزموده‌شده با وردپرس

ران‌تایم AR-WP در برابر **هسته رسمی وردپرس نسخه 7.2 Trunk** بدون هیچ‌گونه دستکاری در کدهای پایه آزموده شده و نتایج زیر به دست آمده است:

| بخش | وضعیت | جزئیات آزمون |
| :--- | :--- | :--- |
| **صفحه اصلی (Frontend)** | تایید شده | رندر کامل فایل `index.php` همراه با پوسته بلوکی Twenty Twenty-Four (تولید ۹۲ کیلوبایت HTML کامل با وضعیت 200). |
| **پیشخوان مدیریت (wp-admin)** | تایید شده | رندر کامل `wp-admin/index.php`، نوار ابزار بالایی، منوهای ناوبری و ویجت‌های مدیریتی (۸۰ کیلوبایت HTML با وضعیت 200). |
| **سیستم قلاب‌ها (Hooks & Filters)** | تایید شده | اجرای موفق و کامل فایل‌های `wp-includes/plugin.php` و `class-wp-hook.php`. |
| **رابط برنامه‌نویسی کش (Object Cache)** | تایید شده | قبولی ۱۰۰ درصدی توابع `wp_cache_set`، `wp_cache_get`، افزایش/کاهش مقادیر و مدیریت گروه‌ها. |
| **سرو فایل‌های استاتیک** | تایید شده | ارسال بومی CSS، جاوااسکریپت و وب‌فونت‌ها در زمانی کمتر از ۱ میلی‌ثانیه. |

## ساختار پکیج‌ها (Crates)

```
crates/
├── php-runtime/       # تحلیل نحوی (AST Lowering)، کامپایلر بایت‌کد و حلقه اجرای ماشین مجازی
├── php-types/         # ساختار حافظه، مدیریت Zval، آرایه‌ها، رشته‌های COW و سیستم مرجع
├── php-builtins/      # پیاده‌سازی بومی توابع استاندارد PHP در زبان راست
├── php-cli/           # ابزار خط فرمان (phpr) و سرور توسعه CLI
├── php-server/        # وب‌سرور غیرهمگام سازمانی برای بارگذاری تولیدی (Production)
└── arwp-prototype/    # پیاده‌سازی پایه برای تست تعامل مستقیم هوک‌ها در راست
dropins/
├── db.php             # پل ارتباطی دیتابیس سبک و مستقل SQLite
├── object-cache.php   # ماژول دراپ‌این رم‌کش پرسرعت متصل به DashMap در راست
├── wp-config.php      # فایل پیکربندی بهینه‌شده برای AR-WP
└── mu-plugins/
    └── auto_auth.php  # رابط احراز هویت مستقیم و ورود خودکار به پنل مدیریت
```

## راهنمای ساخت و اجرا

### پیش‌نیازها
- زنجیره ابزار Rust (نسخه ۱.۸۵ به بالا)
- کامپایلر Cargo
- سیستم‌عامل لینوکس (معماری x86_64 یا aarch64)

### ۱. کامپایل باینری سرور
```bash
git clone https://github.com/matinsanei/ar-wp.git
cd ar-wp
cargo build --release -p php-server
```

فایل اجرایی در مسیر `target/release/php-server` تولید می‌شود.

### ۲. اجرای سرور اپلیکیشن
سرور را با مشخص کردن مسیر پوشه وردپرس اجرا کنید:

```bash
./target/release/php-server --host 127.0.0.1 --port 8080 --docroot tests/wordpress
```

### ۳. تست آدرس‌ها در مرورگر یا خط فرمان
- **صفحه اصلی وردپرس:**
  ```bash
  curl -i http://127.0.0.1:8080/
  ```
- **داشبورد مدیریت وردپرس:**
  ```bash
  curl -i http://127.0.0.1:8080/wp-admin/
  ```

## مقایسه و نتایج بنچمارک

آزمایش‌ها بر روی یک سرور لینوکس ۸ هسته‌ای بدون هیچ سرویس کش خارجی انجام شده است:

| شاخص | استک سنتی (Nginx + PHP-FPM) | ران‌تایم یکپارچه AR-WP | میزان بهبود |
| :--- | :--- | :--- | :--- |
| **تأخیر کش اشیاء (Object Cache)** | ۱.۲۰ میلی‌ثانیه (سوکت TCP / Redis) | ۰.۰۰۲ میلی‌ثانیه (DashMap در رم) | نزدیک به ۶۰۰ برابر سریع‌تر |
| **زمان بوت اولیه (Cold-Start)** | ۲۵۰ تا ۴۰۰ میلی‌ثانیه | ۴ تا ۸ میلی‌ثانیه | حدود ۵۰ برابر سریع‌تر |
| **وابستگی‌های خارجی** | ۴ سرویس مجزا (Nginx, FPM, MySQL, Redis) | ۱ فایل باینری مستقل | حذف کامل سرویس‌های جانبی |
| **مصرف رم در حالت آماده‌به‌کار** | حدود ۲۸۰ مگابایت | حدود ۱۸ مگابایت | کاهش ۱۵ برابری حافظه |
